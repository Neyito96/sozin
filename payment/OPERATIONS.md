# SOZIN 電子決済：導入手順書（検討用）

更新：2026-11-12 / 管理Issue [#8](https://github.com/Neyito96/sozin/issues/8)

## 目的
SOZINの制作受注ごとに、銀行振込に加えオンライン決済の選択肢を設ける。Wixへの移植とは独立してGitHub Pagesで案内ページを運用できる。

## 推奨する初期運用（個別決済リンク）
1. お客様から依頼内容を確認し、仕様・数量・納期を固める。
2. 社長が**正式な請求金額と支払い条件を承認**し、請求書を発行する。
3. 審査・契約が済んだStripe等の管理画面で、**その案件専用**の請求書または支払いリンクを作成する。
4. 社長が請求先・税込金額・請求番号・通貨・期限・重複請求を確認し、お客様へLINE/メールで送る。 `payment/` 公開ページに個別決済URLを貼らない。
5. お客様は決済事業者の安全なホスト型画面でカード等の決済を行う。GitHub Pagesではカード番号/CVVを収集しない。
6. **決済事業者の管理画面の支払いステータス**と銀行口座入金を照合して入金確認する。完了URLへの移動だけでは入金判定しない。
7. 取消・返金・再請求時は取引IDと請求番号を照合し、二重決済を防ぐ。

## 候補サービス比較（導入前に最新料金・審査を再確認）
| 方式 | 長所 | 注意 |
| --- | --- | --- |
| Stripe Payment Links / Invoicing | 個別金額の請求、ホスト型決済 | 手数料、請求書機能の料金体系と本人確認 |
| Square 請求書・オンライン決済 | 請求書発行と決済をまとめられる | 機能・料金・対象決済手段を確認 |
| Wix請求書 / 決済リンク | 既存のWix管理画面に寄せられる | Wixプラン、対応プロバイダ、取引手数料を確認 |

## 運用前チェック
- [ ] 代表による決済事業者の選択、法人口座・本人確認
- [ ] 手数料、入金タイミング、明細・領収書、消費税・インボイス制度の適合を経理担当へ確認
- [ ] 支払い期限、キャンセル・返金、再制作時の対応を確定
- [ ] 請求番号による二重払い防止の運用
- [ ] 事業者のテストモードで決済・失敗・返金を確認
- [ ] テスト・ダミーのリンクを本番ページに混在させない
- [ ] 代表の本番接続・課金開始承認

## 技術的な限界
GitHub Pagesは静的ホスティング。決済事業者が発行した**固定URL**へのリンクはできるが、閲覧者が入力した金額を信頼して自動請求する構成は採用しない。毎案件の決済リンクを自動発行し、決済完了を自動反映するなら、バックエンド側の認証、秘密鍵管理、署名つきWebhookの検証、注文DB、重複処理が必要。

**現段階のpayment/は案内用の試作であり、決済ボタンは無効。**
